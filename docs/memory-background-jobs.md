# 记忆后台任务模块

本模块把消息原文、派生任务、执行恢复和后台用量连接成持久闭环。它只处理记忆派生，不调用业务工具、不批准外部操作、不恢复主 Agent 会话。检索读取与后台补建分离，后台不可用时保留原有对话降级方向。

## 持久化与恢复

PgEpisodeStore 通过 JdbcMemoryJobs 在同一事务写入 messages 与配置要求的 INDEX、DISTILL 任务。每条新用户消息单独登记提炼任务，助手消息只登记向量任务；框架标记为 synthetic 的消息不进入原文或偏好来源。任务主键由类型与稳定消息身份组成，重复历史回调不重复登记；登记失败时原文与任务一起回滚，本地去重缓存不提前确认成功。存储不可用期间的原文仍依赖后续会话回调补记，不能宣称数据库故障时已保证接收。

作业状态为 READY、RUNNING、RETRY、DONE、DEAD。领取使用短事务与 SKIP LOCKED，执行带 owner、generation 和数据库时间租约。外部模型或向量请求不占用作业事务；返回后先持久化带 schemaVersion 的结果检查点，再在受围栏保护的完成事务中写入画像、实体或向量并确认 DONE。检查点已经保存时，重启或提交失败后的恢复直接使用该结果，不再次调用供应商。旧代次无法覆盖检查点、发布派生数据或确认新作业。

未保存的网络结果无法做到供应商级 exactly-once。若供应商已处理请求、进程却在保存结果前退出，恢复可能重复调用；调用次数预占和未知用量会保留，不把这段消耗退回或归零。普通失败默认最多三次处理尝试，已有检查点另外允许两次恢复机会，之后进入 DEAD。重试采用有上限的指数退避。单次输入超过整日输入额度属于不可满足的输入限制，有限重试后可见失败，不会永久占据等待次日的队列首部。

## 画像与实体保护

提炼模型读取严格画像快照，只展示能完整放入上下文的页面，最多二十页、页面上下文合计二万字符，不从截断正文重写整页。输出条目和字段长度有界，重复页面身份与非有限置信度不能通过。模型最长等待三十秒，输出 token 上限为 2048。

同一实例或不同实例的提炼作业通过数据库通道串行领取，前一项退避时不越过它处理后续提炼。画像更新同时检查 revision、人工来源、删除标记与 source_position；迟到或人工重提的旧来源不能覆盖更新的推断。人工编辑和删除仍受到保护，保留页面时作业记录 PRESERVED_NEWER_OR_MANUAL，而非伪装为覆盖成功。未展示的已有页面只可能走插入冲突，不会被自动覆盖。

实体派生写入带 source_message_id 和 derivation_key，同一消息重复应用不会重复插入同一三元组。原文、画像及实体并不是同一个删除范围；本模块沿用画像删除语义，不把删除画像扩张为整库擦除。

## 有界执行与历史召回

持久消费者默认并发二，使用无等待缓冲的执行池与槽位控制。未取得槽位的任务留在 PG，不转到请求线程执行。可重建的画像向量缓存与习惯扫描使用独立单线程、有界队列，默认容量三十二；拒绝可观察，缓存可在后续读取时重建。关闭 MIO_MEMORY_JOBS_ENABLED 会停止后台消费与临时后台任务，不删除已登记作业，不关闭前台记忆读取。

历史扫描每次最多一百条，以消息 id 游标持久推进，没有两千条停止上限。待处理索引达到一千条时暂停历史扫描，避免一次性制造过大补建积压；新消息任务仍会原子登记，优先于历史补建。历史只补向量，不自动把所有旧用户表达重新提炼为当前偏好。

召回先检索向量，再按命中 id 有界回源 messages，不加载全量原文、不依赖进程内历史元数据缓存。不存在原文、相似度不达标或分数非有限的命中被丢弃；索引写入拒绝非 1024 维、非有限或零向量。已有历史向量可在后台尚未补完时立即参与召回。清空向量或改变模型属于显式重建迁移，不会自动复用旧完成状态；不要混用不同模型产生的向量。

## 后台用量与额度

画像提炼、持久情景向量和后台画像向量调用在供应商 I/O 前登记用量预占。范围仅为后台工作，前台查询向量及其他 Agent 模型调用仍沿用其原有路径，不把本账本冒称账户所有模型调用的总账。默认按 UTC 日限制二百次调用、四十万输入字符和二十万已报告 token，可分别通过 MIO_MEMORY_DAILY_CALLS、MIO_MEMORY_DAILY_INPUT_CHARACTERS、MIO_MEMORY_DAILY_KNOWN_TOKENS 调整。

调用次数与输入长度先预占；token 是供应商实际返回的用量，不能当作费用硬上限。DashScope 向量客户端读取原生 usage.total_tokens；画像模型按流式报告核实最终用量。缺失、超时或进程退出后未完成的用量保留 PENDING 或 UNKNOWN，过期预占会转为 UNKNOWN；晚到且关联明确的完整用量可以补成已知。额度耗尽前阻止新的供应商调用，作业延后到下一 UTC 日，不消耗失败重试次数；重启不重置当天账本。

## 诊断与运维

面板“画像”视图展示记忆后台状态、积压、重试、失败、用量缺口和缓存拒绝数。GET /api/memory/jobs 为本机只读入口，沿用现有回环访问控制，不提供重试、清空或预算修改操作，不返回消息正文、模型结果检查点或凭据。状态读取失败返回 503，界面不能显示为零积压或零用量。

上线前备份数据库并停止旧进程，再让 PgMemoryConfig 幂等建表、补列；新旧执行路径不能混合部署。启动完成后才开始轮询，缺少配置的服务不会领取相应任务。缺凭据时保留任务，修复配置并重启后继续；配额延后自动等待重置时间。DEAD 作业需要先核对错误原因与源消息，修复问题后由维护者针对明确 id 重新置为 RETRY、清空 owner/lease、增加 generation 并重置尝试次数，保留已保存结果与全部用量。不要批量删除原文、作业或用量来解除限制。

当前没有后台业务调度，也不承诺无限数据库容量或供应商账单硬限制。该模块提供有限重试与可诊断终态，不能将所有失败都自动标为已完成。

## 离线验收

运行 `./scripts/eval-postgres.sh`，使用隔离的 pgvector/pgvector:pg16 容器，仅监听回环地址，不读取业务凭据；模型为替身，向量客户端契约测试只访问本机合成 HTTP 服务。完整验收要求 Java 17、Maven、Python 3、Node.js 18+ 与 Docker。

JdbcMemoryJobsIntegrationTest 覆盖原文/任务原子回滚、竞争领取、租约过期、检查点恢复、事务回滚、人工编辑与删除、旧来源、有限重试、额度延后、实际消费者并发，以及 2105 条混合历史的尾部召回和分页登记。大历史测试通过完成状态推进补建窗口，向量实际写入及重启恢复由独立实库用例验证，不把两千条登记冒称两千次真实模型采样。JdbcMemoryUsageIntegrationTest 验证并发额度、重启不归零、未知和晚到用量、过期执行拒绝预占。MemoryBackgroundBoundaryTest 验证有界队列、只读诊断与实际客户端的先预占后 I/O。前端模块由 `node --test scripts/test-memory-jobs-panel.mjs` 验证并纳入 Python 门禁。
