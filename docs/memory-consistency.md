# 记忆一致性与人工编辑保护

长期记忆允许失败降级，但失败不能被当作成功记录，也不能让旧的推断结果覆盖用户的新决定。本次修正沿用 PG 原文与派生索引的存储边界，覆盖消息身份、画像竞争写入和人工操作反馈。

新消息以会话标识与 AgentScope 消息 id 生成完整 SHA-256 身份，使用 msg-v2- 前缀。相同文本的不同消息、不同会话分别保存；同一消息的全量历史回调及进程重启后回调由 PG 主键幂等。插入入口区分新增、已有和失败；已有行还需匹配会话、角色和原文，身份冲突时保留原文并拒绝建立新索引。原文与配置要求的派生任务现已同事务登记，本地缓存只优化已确认消息的重复访问。写失败不进入缓存，同一消息再次出现时可以补记。

历史消息及历史向量保留原 id，不推断它们与新 SDK 身份的对应关系。升级后的首次历史回调可能产生一份使用新身份的原文；不存在可可靠迁移的源消息 id 时，不按文本强行合并。消息补记依赖后续回调；已确认落库的消息则由持久化后台作业恢复，检查点、重试和用量边界见[记忆后台任务模块](memory-background-jobs.md)。

画像增加 revision 与 deleted_at，旧行默认版本零。启动幂等补列，原正文与来源保持不变。提炼器在调用模型前读取一次严格快照，只能按该快照的版本更新 inferred 页面。人工维护的 explicit 页面即使版本匹配也禁止自动覆盖；新页面仅在该身份从未存在时创建。并发提炼使用同一旧版本时最多一个成功。模型调用最多等待三十秒，超时按背景提炼失败处理。

删除画像清空正文与消息引用，并保留页面身份及删除版本。旧提炼结果和后续自动提炼都不能以相同 id 复活页面；用户明确执行人工保存时可以恢复。保护按页面身份实施，不宣称识别模型换名生成的语义重复内容，也不将画像删除解释为源会话、实体簿和向量的全库擦除。删除语义与所有数据的留存清理仍是不同操作。

对话注入仍可读取失败后降级为空；画像面板读取、人工保存和删除使用严格入口，数据库不可用返回 503，响应不泄露数据库细节。删除结果不明时界面保留原内容并提示刷新核对，不能把失败显示为已删除。当前版本检查约束后台提炼与人工编辑的竞争，人工客户端之间的编辑仍使用最后一次明确保存，不宣称已提供多人编辑冲突合并。

`MemoryRecordingTest` 覆盖消息重放、相同文本、失败补记与框架合成消息过滤；`ProfileConsistencyTest` 覆盖读取失败时不调用模型、人工 API 错误。`JdbcMemoryConsistencyIntegrationTest` 使用隔离 PG，验证旧表升级、不同实例竞争写入、人工页面保护、删除后不复活、真实提炼器在模型返回期间遇到人工修改，以及原文身份冲突。完整验收入口仍为 `./scripts/eval-postgres.sh`，默认不调用真实模型或业务接口。
