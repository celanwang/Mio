# 证据驱动决策与交付

统一目标：让 Mio 依据当前证据修正准备计划，保留有效成果，并交付有来源、有取舍、有下一步操作的结果。

实现分为三个阶段。第一阶段完善文档融合排序、精确引用、可暂停恢复的后台索引和受限网页正文读取。第二阶段把当前计划、步骤成果、失败和资源状态加入规划上下文，生成局部变更建议，明确保留、修改、删除及受影响步骤；增加带硬条件和权重的多指标比较。第三阶段把证据、缺口和下一步操作组织成交付报告，减少当前计划查询对全部任务历史的依赖，并统一页面轮询。

计划建议始终是未采纳数据，用户确认后才改变执行范围；准备计划不能批准外部业务写入。未知操作不通过重规划重放。引用核对证明片段与版本一致，不证明片段中的观点正确。网页正文来自显式配置的 HTTPS 域名，作为不可信资料处理。后台索引只在用户显式启动后消费知识预算，文档或模型版本改变后旧结果不发布。

每阶段提交可用功能和必要回归；测试使用隔离数据库和本地响应，不联系真实业务或付费模型。

## 知识与引用

文档查询分别取得关键词与语义候选，再用 RRF（1/(60+排名)）合并，同一分块去重，同篇文档最多三块，最多返回20块。未配置向量服务时只使用关键词。关键词仍为文本子串匹配，尚未引入中文分词或付费重排模型。

搜索结果包含 documentId、revision、startOffset/endOffset。read_document 支持 expectedRevision、endOffset 和 quote，GET /api/documents/{id}/citation?revision=...&start=...&end=... 也可核对引用；quote 可选，传入时必须与该范围全文一致。引用失效会明确报错。sourceHash 用于识别当前内容，不能证明来源观点正确。

工作台“后台构建或恢复索引”登记持久任务，单工作线程每批最多16块。可以“读取索引进度”和“暂停后台索引”，重新启动会保留已有分块成果；失败最多重试三次，此后需显式恢复。暂停取消发布租约，不声称撤销已经产生的供应商调用费用。旧文档或旧模型任务取消，文档删除级联移除索引作业。恢复数据库时暂停索引任务，避免备份中的作业自动继续消费。

POST /api/documents/{id}/index-jobs?expectedRevision=... 启动或恢复，GET 同一路径读取状态，POST /index-jobs/{job}/pause 暂停。原来的单批 /index 接口仍可使用。

研究助手的 read_web_page 默认不开放域名。MIO_RESEARCH_ALLOWED_HOSTS 显式配置精确域名列表，支持 HTTPS/443，拒绝内网解析、内嵌凭据、片段和跳转。管理员需信任配置域名及其 DNS，域名配置不是给任意网站浏览的沙箱。正文最多512KB、15秒，HTML 去除脚本及样式后按16000字符分页；URL、sourceHash、observedAt 与偏移作为引用。后续分页传 expectedHash，页面变动则拒绝旧引用。当前优先处理 UTF-8 HTML、纯文本和 Markdown，不执行 JavaScript，不支持登录网页或二进制文档。公开搜索、远程准备也使用完整响应的大小和时间限制。

## 局部计划与比较

工作台“根据当前证据修订计划”使用一次无工具模型调用。输入包含实际用户意图、当前步骤定义、截断且标明的任务报告、独立的事实评估、有效事实、资源来源与未知操作编号。模型输出字段增量、步骤新增或修改、删除和重试编号；未输出步骤原样保留。目标字段与验收条件不能由模型移除或改写，确需调整由用户编辑或更新实际目标。用户目标版本变化时重新生成完整计划。

预览列出保留、修改、刷新、新增、删除，以及字段、条件和执行范围的变化。保存采用既有字段版本与步骤 generation 规则，使修改影响的下游重新准备。建议记录 evidenceHash，生成结束和采用时核对任务版本、事实过期及资源最新观测；变化后需重新生成。直接用户编辑仍可修改目标条件，不把模型建议提升成业务授权。

POST /api/goals/{session}/program/preview 预览，原 /program PUT 确认。Request 新增 refreshSteps、evidenceHash，可兼容旧请求。

“多条件方案比较”支持候选步骤、1至8个数值指标、明确单位、MIN/MAX 偏好方向、正权重，以及可选 EQ/LTE/GTE 硬条件。先核对有效可信事实及已确认步骤条件，缺数据、单位不一致、过期或不满足条件的候选保留并解释原因；只对可选候选按本次范围的极值归一化，再计算加权得分。常量指标给所有候选相同分，同分按步骤编号展示。得分是偏好比较，不是概率或授权。现有业务契约能提供的指标才可比较；报告中声称的数字不自动变成可信事实。

POST /api/goals/{session}/comparisons 保存比较，GET 读取最近10次。请求包含 expectedRevision、expectedGoalRevision、stepIds 和 criteria；指标含 fieldId、unit、direction、weight、operator、expected。结果、权重和证据版本持久化，计划或证据变化后只作为历史展示。

## 交付与运行

工作台显示确定性的结论、缺口与下一步，提供修订计划和推进入口。报告完成明确标记为报告范围，不等同于业务事实或履约完成。Markdown 包含当前比较的条件、权重、得分和证据，逐步骤输出与事实来源，以及确认的字段和条件。

“综合当前证据与取舍”显式消耗一次目标模型额度，沿用计划生成的预算与期限，不访问工具、不提交业务。POST /api/workspace/goals/{session}/synthesis 的 expectedHash 取当前工作台 decisionHash。模型返回 summary、findings（text、stepIds）、tradeoffs、gaps、nextSteps；校验长度及来源步骤，证据变化不发布。引用到步骤仅保证来源编号存在，不证明每句话都由来源支持，综合界面和报告均标明模型解释。确定性缺口始终保留，综合不会改变 ready 或权限。

综合按 decisionHash 保存，交付 sourceHash 额外包括综合内容，因此综合更新会生成新的交付版本；旧交付保持不变。页面轮询只读取状态，不触发模型。当前计划任务按目标版本及任务 key 查询，资源核查按关联任务编号查询，旧 generation 不反复进入每一步查找；提交时的跨任务副作用检查仍保留完整安全判断。

数据库新增 V003 至 V005，均经统一迁移校验。索引调度为一个专用线程；工作台轮询串行、后台标签页暂停、复用进度和资源快照，忽略切换目标后的旧响应。这里没有引入 Redis、独立向量库、微服务或新的 Agent 框架。
