# 前台模型用量收尾

本模块补齐多 Agent 前台模型调用的用量终态：正常完成、异常、取消与进程中断均保留已预占的调用次数，不因断线或失败退回额度。覆盖通过 BudgetedModel 的主助手和领域助手；Jev 等没有用量回报的审核调用仍保留 UNKNOWN。它不统计账户内所有模型、查询向量或供应商账单，也不调度业务任务。

## 调用与终态

模型网络 I/O 前，RunBudget 同时消费单轮额度并在目标账本预占调用，持久化 PENDING。预占完成后再次检查单轮截止时间、执行租约与目标控制状态；数据库等待期间超时或目标停止，不能继续发起模型请求。调用次数仍保留，不通过释放预占来突破额度。

流式用量按已观察的累计 token 最大值计算，最终回报完整且与累计值一致时结算 KNOWN。缺失最终用量、异常或取消时结算 UNKNOWN，并保存取消或异常前已观察到的消耗下界。token 结算提交后才向 Agent 暴露模型返回的工具调用；未完成或超额的结果不能触发工具执行。取消通过 boundedElastic 执行上游清理与账本写入，避免在取消方事件线程执行 JDBC；清理可能稍晚于订阅取消完成，页面短暂显示 PENDING 属于正常过渡。

取消清理写库失败时保留 PENDING，记录不含正文的告警，不伪装为零消耗。尚未持久化的部分 token 不能在进程退出或数据库故障后准确重建；后续恢复标记 UNKNOWN，不把未知用量解释为零费用。调用次数、目标 token 下界及历史覆盖标记不会因重启重新初始化。

## 截止恢复

budget_calls 增加 expires_at。新调用以数据库时钟持久化截止时间，时长取本轮剩余时间加五秒收尾余量，最长十五分钟；不把应用机器的绝对时间写成数据库截止点。直接通过账本预占模型调用时默认十五分钟。单轮服务仍受已有最长 895000 毫秒约束。

启用 Multi-Agent 后，GoalUsageRecovery 在 ApplicationReadyEvent 后启动，每五秒最多扫描一百条已截止 PENDING。每项使用短事务，先锁目标账本、再核对调用状态与数据库时间。繁忙预算行使用 SKIP LOCKED，下一轮再处理。恢复只将仍已截止的 PENDING 转为 UNKNOWN，保留原 token 下界，不修改任务、审批、租约、操作占位或目标意图。主从执行及业务写入不会被恢复器重新运行。

多实例可以同时恢复或接收晚到用量。调用状态、目标计数和预算审计同事务提交；陈旧候选重新核对后忽略。审计失败回滚，数据库恢复后可再次处理。单笔账本事务最多十秒，恢复中的锁等待上限一秒；失败告警限频三十秒。积压按固定批次逐轮推进，不承诺所有历史预占在一次 tick 内完成；进程停止后由下次启动继续。

## 迟到的可信完整用量

同一个内部调用编号可将 UNKNOWN 补为 KNOWN，完整 token 必须不小于已报告下界。只追加差额并减少一个未知计数，不再次消费模型调用额度；完全相同的重复回报无效果。KNOWN 的值不能改写，较小回报或属于其他目标的编号被拒绝。补记触发累计 token 超限后，后续模型和工具预占仍被阻止。

调用编号由服务端内部持有，没有供模型或网页任意填写用量的接口。当前关联补记能力用于保留回调仍能到达时的完整模型回报；进程已失去回调且供应商不提供关联证据时，用量继续未知。本轮不提供人工填零、预算重置或自动增额入口。

## 升级与诊断

升级前停止旧版本实例并备份，沿用当前项目的幂等初始化方式补列与索引，不混合部署旧模型预占路径。旧 PENDING 的 expires_at 默认为零：没有可证明仍存活的执行身份，启动后按有界批次转 UNKNOWN。既有 KNOWN、UNKNOWN、累计次数、token 与 historyUnknown 不被重置。正常进程中断由本模块处理；备份恢复仍需执行[发布维护流程](release-maintenance.md)撤销旧运行身份，不能仅靠等待用量过期代替。

页面现有预算区域显示 PENDING/UNKNOWN；GET /api/tasks 继续只读取账本，不在查询时触发恢复。budget_usage_expired 事件记录自动恢复后的账本状态，迟到完整补记使用 budget_settled，事件编号带 usage_completed 以区分首次终态。暂停或关闭目标不阻止已发生调用的用量收尾，补记不会恢复目标或批准业务操作。

## 验收

PersistentBudgetTest 覆盖取消、部分流用量、超限工具阻断和数据库等待越过截止时间后的 I/O 阻断。GoalUsageRecoveryTest 验证启动时机、固定批次与故障后下一轮重试。JdbcGoalUsageIntegrationTest 在隔离 PostgreSQL 中验证旧表迁移、重启、截止时间、并发终态、迟到补记与审计回滚、取消清理失败恢复、忙碌行跳过和额度不退回。

JdbcGoalLifecycleIntegrationTest 另从实际 SDK 前台服务发起请求并取消，验证模型预占转为 UNKNOWN、会话执行租约释放、取消结果不写入 SDK 检查点，目标仍保持原 ACTIVE 状态。

完整入口为 `./scripts/eval-postgres.sh`，新增用量套件纳入十个必跑 PG 套件，必须同次运行且零跳过。模型使用替身，业务工具不访问真实供应商；OFFLINE_COMPLETE 的含义和产物来源约束沿用[收尾验收](multi-agent/closure.md)。
