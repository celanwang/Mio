# 完整前台编排的离线验收

`JdbcOrchestrationAcceptanceTest` 用同一条前台业务链连接真实 SupervisorFactory、DomainAgentFactory、MultiAgentChatService、TaskRuntime、权限确认、PG 检查点、执行租约、累计预算、任务证据、事件发布及原文记忆。模型输出使用确定性剧本，业务工具操作独立的合成状态；不需要模型密钥，不使用真实供应商。

场景从用户原话开始，由主 Agent 发现两个独立能力，委派报价任务，再把持久化事实及其版本绑定到另一个能力的分析任务，随后请求经人工确认的创建操作。用户先通过真实控制器确认验收条件，包括行程耗时上限与资源创建证明；这一步不改变模型预算、用户意图或业务批准。报价输出要求可信事实，分析输出是工作报告，创建输出要求资源证据。批准前合成世界不能出现资源；批准后仅有一次创建并满足确认范围，拒绝后资源仍不存在，验收条件不能全部满足。

验收同时检查三个领域任务和主 Agent 的检查点、模型调用对应的预算记录、已报告 token 与结算事件，以及再次读取时预算和任务不丢失。批准路径十二次模型调用，拒绝路径十一调用；拒绝在服务端取消任务，不再恢复领域模型。模型为替身，调用指实际执行模型接口及 SDK 循环，不是付费模型网络采样。顶层原话和主助手回复进入 PG 原文，委派工作说明不进入用户记忆；画像提炼和向量化在该场景关闭，不能宣称其模型质量已经验证。

这个套件是完整前台编排路径的工程回归，和原来的 skill-and-permission-simulation 采样器有不同评测目标。固定剧本仍然不证明自由规划能力、跨领域完成率、价格或时延优势。真实模型多次采样、与单 Agent 的相同预算对照、自然语言目标条件的完备性及人工审查仍须另行提供证据。

完整运行仍为 `./scripts/eval-postgres.sh`。收尾门禁包含本套件，连同持久化、队列、目标生命周期、记忆一致性和目标验收十类 PG 套件（含发布维护、真实备份恢复及前台用量恢复），要求同次运行且全部零跳过。输出契约说明见 [任务输出契约](result-contracts.md)，条件确认和状态口径见 [目标级验收](goal-acceptance.md)。

记忆后台新增作业与用量两个必跑实库套件，使用隔离 PostgreSQL 16 + pgvector；运行及恢复说明见 [记忆后台任务模块](../memory-background-jobs.md)。
