# Multi-Agent 运行时

目标方案：[Iris Multi Agent Design](https://q0kyes8lnt5.feishu.cn/wiki/SVz6w01hui1eKekTFqbcLHEinXg)。主 Agent 通过能力注册表委派任务，领域实例隔离上下文与工具，业务动作仍经确定性权限检查与任务级人工确认。

实现按模块推进：任务/能力契约与 PG 存储；主从调用与确认恢复；领域接入、入口开关及本地集成评测。高级后台事件调度、按事实依赖选择性重规划和生产资格评测另有验收要求，不能仅凭固定模型测试宣布完成。

`goals`、`tasks`、`agent_states` 的 DDL 见 [schema.sql](../db/schema.sql)。新增协作关键状态不回退内存；状态更新检查 revision 并与稳定身份的审计事件同事务提交。测试中的内存存储仅为 test double。SDK 会话 checkpoint 与业务操作记录有不同职责，恢复期间不能把一个已开始副作用的调用直接重跑。

RunBudget 由主从请求共用，限制前台模型/Jev、工具、子任务恢复次数、token、上下文大小和执行时间。目标级账本在 PostgreSQL 中累计跨轮消耗，重启、审批、定向回答和任务恢复均不重置额度。未返回模型 usage（包括 Jev）时显式标记不完整；并发调用、后台长期记忆提炼及服务端计费存在边界，不能据此声称精确费用上限。

## 受控预览

在 `.env` 中显式设置 `MIO_MULTI_AGENT_ENABLED=true` 后重启，`/chat` 由主 Agent 处理。默认仍关闭，保留原单 Agent 入口。开启时初始化 `goals`、`tasks`、`agent_states`、`goal_budgets` 和 `budget_calls`；数据库故障会停止协作执行，不回退到空状态继续操作。现有记忆表 `events` 也必须已存在。

主 Agent 使用发现、委派、查看、继续、取消任务和关联操作核查六种受控工具。三个领域各有独立技能视图与工具目录；主 Agent 不直接拥有供应商原始业务工具，关联核查由服务端适配器限制为已有操作的读取。新增领域通过 `DomainDefinition` 注册，核心运行时没有品牌路由分支。当前主模型负责协调、标准模型负责领域执行，Jev 用于领域写操作意图审核；沿用原入口时保留原有路由。

`discover_agents` 返回 capability 与 availability，使用 capability.id 委派。可用性是执行时重新读取的本地观测，状态分为 READY、PREPARATION_REQUIRED、UNAVAILABLE、UNKNOWN，携带原因码、说明、准备工具白名单及观测时间。READY 仍须遵守原权限链，不授予任何业务写权限；当前三个领域不会仅凭工具加载或配置存在就发布 READY。

领域 Agent 使用实际 `ReActAgent` 和 `ChatService` 权限恢复链，完成或补问分别通过任务控制工具明确结束。内部委派消息不进入长期记忆，Jev 的授权依据固定为主会话真实用户表达。主 Agent 只记录真实主对话；受控画像读取仅包含全局和当前领域页，不隐式触发额外检索模型。

每次人工确认在服务端关联子任务、子会话、原调用 id、递归冻结的参数、参数指纹和工具契约指纹；客户端仍只提交不透明确认编号和布尔决定。默认五分钟过期，真正发出业务请求前再次检查有效期和指纹。批量工具调用允许逐次记录决定，但该子任务全部调用都已决定后才恢复。普通全局消息会保守地使旧待批准任务变为 STALE；显式定向回答只更新对应任务，不使无关的有效审批失效。任务绑定领域技能目录的内容哈希，版本改变不能恢复旧任务。全局消息尚未按事实依赖做选择性失效。

PREPARE 任务不能执行写操作。REQUEST_APPROVAL 仍受原权限、Jev 与人工轨约束；不可逆操作在真正提交前再次检查批准及契约。副作用开始前持久化操作标识和参数指纹。缺少可信核验器或有效证据时，写调用返回后仍为 UNCONFIRMED、任务为 UNKNOWN，不能凭框架 SUCCESS 或模型文本宣称业务已成功。一项任务最多提交一个外部写操作，同会话同领域已有未核查提交时不再创建写任务，仍可创建 PREPARE 任务查单。已接入的结构化回执核验与阶段边界见下文。

SDK checkpoint 已存 PG；恢复 RUNNING 任务时不会重跑旧调用，而将其归类为中断/UNKNOWN 后要求核查。NEEDS_INPUT 和有效 AWAITING_APPROVAL 可以通过各自路径恢复；检查点缺失或损坏时停止恢复。同领域操作在目标行锁保护的事务内检查历史提交并落下操作记录，再联系供应商，避免多个待批准任务绕开重复提交限制。后台事件队列、跨 HTTP 请求的长时自主执行、按依赖局部重规划，以及正式生产资格评测尚未交付；当前是前台请求内的主从协作预览，限单应用进程使用，尚未实现多副本下的主会话 checkpoint 并发控制。未知结果不得用新任务、新会话或切回旧入口作为自动重试手段。

## 本地验证

`./scripts/eval.sh` 保留全部离线基线，并执行新增主从和权限回归；不使用 `.github` 或模型密钥。集成测试运行真实主 Agent → 任务工具 → 真实领域 ReActAgent → 人工确认 → 子会话恢复 → 主会话结果回传，只将模型、存储和业务服务替换为 test double。

`JdbcPersistenceTest` 验证真实 SDK 消息多态序列化、损坏检查点拒绝恢复、乐观锁冲突与审计失败回滚。它使用模拟 JDBC 边界，不冒充真实数据库验证。提供测试库的 `MIO_TEST_PG_URL`、`MIO_TEST_PG_USERNAME`、`MIO_TEST_PG_PASSWORD` 后运行 `./scripts/mvn.sh -B -Dtest=JdbcPostgresIntegrationTest test`，可验证 PostgreSQL 行锁竞争、事务回滚及跨存储实例读取检查点。测试自行创建随机 `mio_eval_*` schema，结束后只删除该 schema；没有连接配置时实库测试显式跳过。

页面按任务展示状态和独立决定按钮；待确认期间仍可补充新要求。重新打开页面和请求出错后会回读服务端任务状态，不自动批准或重跑。完成前台请求前无法通过同一个聊天输入打断；取消 API 可以阻断任务后续工具，已经发出的外部请求则保留 UNKNOWN。界面验收使用隔离 HTTP fixture，不触达真实服务。

## 操作核验闭环

操作账本保存在任务 JSON 的 operations 中，与任务版本、审计事件同事务更新。OperationOutcome 与 TaskStatus 分离：UNKNOWN 任务可以接收晚到回执，但不能重新执行。回执按内容指纹去重、追加保留，证据冲突回到 UNKNOWN。写入回执时锁定任务行，取消和并发回执不会覆盖彼此。旧 JSON 缺少 outcome/receipts 时保持未知，兼容既有状态。

核验器仅由可信应用配置注册，模型和客户端没有提交“核验成功”的接口。当前腾讯创建订单适配器仅在实际桥接返回的退出码、HTTP 状态、业务码和字符串订单号均有效时确认创建已发生；这不证明派单、支付或履约完成。核实后解除运行时同领域的不确定性阻塞，供应商自身的进行中订单保护仍生效。框架默认的 RUNNING 状态也可能只是未设置状态，是否核实仍完全取决于供应商证据；ERROR/DENIED 等状态不能通过该核验路径。

其他工具、畸形或冲突回执保持未知，没有根据失败码推导“未执行”。未收到可关联回执的超时操作仍保持阻塞。腾讯创建订单已接入下文的关联回执核查和同凭据范围互斥；其他供应商、资源级完整生命周期保护和供应商幂等键尚待接入。一次任务发出操作后不能继续等待新操作的审批或补问，后续动作需要新的任务并再次经过授权边界。

运行 `./scripts/eval-postgres.sh` 可用 PostgreSQL 16 临时容器执行完整离线入口。容器只绑定本机随机端口、不挂载业务数据，退出时清理；使用已有测试库时仍可设置 MIO_TEST_PG_*。实库覆盖同领域提交竞争、审计失败回滚、检查点恢复及并发晚到回执，模型和业务服务始终使用 test double。

## 结构化事实交接

TaskSummary.facts 提供带来源任务、证据编号、版本、观测时间及有效期的事实，过期快照不再出现在该视图中。已核实创建回执投影类型为 provider_resource_reference 的业务资源编号；原始回执和版本在 PG 中持久保存，编号仅证明资源曾创建，因此没有当前状态的过期语义。另已接入 ride_quote 短时报价快照，用于跨领域的时间与预算分析；库存、司机 ETA 等事实仍需各自的可信提取器，不共用报价的证据规则。

主 Agent 在 delegate_task 的 inputs 中引用 taskId、factId、version、alias，来源必须同时出现在 dependencies；不能传一个自定义值代替引用。运行时校验会话、目标版本、来源完成状态、事实存在性和版本，再将实际值交给领域 Agent。模型文本和框架 COMPLETED 本身均不会生成事实。生产能力现发布 inputContracts，跨任务事实绑定必须显式选择对应 inputContract；服务端校验完整别名与事实类型。旧六参数 AgentCapability 注册仍保留原引用方式以兼容扩展，不能冒充已声明了必填输入契约。运行时仍不能从任意自由文本推断遗漏输入，默认任务不承诺具备跨任务事实；不能将这层契约声称为完整的意图字段校验。

每次工具调用及提交前复核事实。PG 提交事务还锁定来源任务并重新校验，避免读取事实之后、写操作记录之前发生证据变更。当前来源证据产生冲突时事实消失，下游工具被阻断，晚到完成结果也不能覆盖为成功。此处只实现已声明依赖的有效性检查；全局事实修订、主动选择性失效和局部重规划仍待后续阶段。

## 任务级补问与回答恢复

NEEDS_INPUT 任务返回 questionId，绑定任务编号、任务 revision 和问题文本。客户端通过 `/chat` 提交 message 与 taskReply（taskId、questionId），不提交伪造的任务状态、授权或问题文本。服务端核对会话与问题版本，将原始回答、问题及时间写入任务 answers，并与 task_answer_received 审计事件同事务提交。回答只进入对应领域 Agent 的授权上下文，不写入全局目标、不进入主会话长期偏好提炼；不扩大 PREPARE 范围，也不能代替实际工具调用的人工批准。

回答提交后先进入 INPUT_READY，再恢复原子会话。若在这两步之间中断，页面或主 Agent 可以通过恢复入口继续已经保存的回答；`/chat` 的 resumeTaskId 仅接受 INPUT_READY，不重跑运行过、已完成或已提交副作用的任务。恢复、定向回答、批准互斥提交。取消、目标变更或技能版本改变会阻断旧恢复路径，数据库中的旧 JSON 缺少新增字段时按空回答历史读取。

普通消息保留单补问兼容路径：收到消息时恰好只有一个待回答任务才记录候选归属。多个任务同时提问时必须明确选择，不能在其他任务完成后把原先含糊的消息重新分配给剩余任务。普通消息仍属于全局用户表达并触发保守失效，需要避免无关审批失效时应使用定向回答。此处实现路由与版本绑定，尚未为问题定义日期、地点等字段类型或自动判断回答语义是否充分。

回答同时记录所属目标版本，授权审核上下文按全局用户表达及该版本内回答的先后顺序合并。旧回答不会被追加到后来的全局修正之后。全局原始文本仍保留供审计，并与结构化时间线校验一致性；旧 JSON 没有时间线时保留为一个整体快照，不通过可能出现在用户文本中的分隔符猜测历史。此处保证证据顺序，不代替字段语义校验或确定性的授权边界。

页面提供“回答此任务的问题”与明确的回答上下文。响应失败后会回读任务，已失效的问题不能重发，也不会自动改成全局消息；INPUT_READY 可以点击“继续此任务”。审批和恢复控制保留输入草稿。任务区与输入区独立滚动，避免大量任务挤出输入区。多 Agent 模式下的微博授权状态检查只更新授权提示，需在对应任务继续回答，不将状态回调伪造成用户新意图；旧单 Agent 入口保持原交互。隔离 HTTP fixture 验收覆盖多补问、无关审批保留、持久回答后的响应失败和恢复请求参数。

## 跨轮目标预算

新增目标默认累计上限为 160 次前台模型/Jev 预占、320 次工具预占、48 次任务恢复预占和 320000 个已报告 token。分别通过 MIO_MULTI_AGENT_GOAL_MAX_MODEL_CALLS、GOAL_MAX_TOOL_CALLS、GOAL_MAX_TASK_CALLS、GOAL_MAX_TOKENS 配置（后面三项也带 MIO_MULTI_AGENT_ 前缀）；原有每请求限制同时生效。首次开户时固定该目标额度，修改配置或重新发请求不会扩充已有账本。当前一个会话对应一个目标，尚无自动增加额度、定期清零或目标内再开户入口；该预算也不是账户级日费用限制。

开户、预占、结算和对应审计事件同事务更新，目标行锁防止并发超领次数额度。模型预占先于网络请求，已有预占不会因为取消或异常而退款。正常返回按 SDK 累计 usage 口径取最大值一次结算；缺失最终 usage、流中断或无效用量标为不完整。取消后尚无结算的调用保持 PENDING，进程重启不会把它当作未调用。Jev 未提供 usage 时记 UNKNOWN，仍占模型次数额度。已观察到的部分用量作为已知下界保存，不能等同于最终账单。

达到已报告 token 阈值后阻止后续预占；返回用量超过阈值的模型结果不会把工具调用交给 Agent。输入费用、并发在途请求、缺失 usage 及后台记忆模型消耗均无法用这个阈值精确预付控制，因此它是停止阈值而非费用硬上限。审批执行额度不足时不消耗最后一项人工批准；拒绝全部操作直接取消任务并保存拒绝证据，不恢复领域模型、不占执行额度。取消任务的控制 API 和读取状态也不扣执行额度。预算错误返回 HTTP 429，不自动重试业务动作；主模型无额度时仍可能无法生成自然语言回执，控制结果可从任务状态回读。

`/chat` 及 `/api/tasks?sessionId=...` 的 budget 字段返回目标额度、累计预占、已知 token、pendingUsage、unknownUsage、historyUnknown 和 usageComplete。已有目标首次启用账本时，旧用量不可追溯，historyUnknown 保持 true，不声称历史零消耗。新目标从首轮开始记录；全局修订和定向回答复用目标编号及同一账本。无预算记录的只读查询不会创建账本。当前页面尚未展示预算明细，可由接口和执行事件读取。

## 能力发现与运行前检查

发现不会连接供应商、刷新 OAuth、执行 Python 或调用真实业务接口，也不探测账号体验额度。MCD 工具未接入时不可委派，工具已加载时只报告未在线验证。腾讯出行检查本机启用项、凭据是否配置、可执行文件和桥接脚本是否存在，不读取或回传凭据内容，不执行版本探测；本地条件具备仍需实际 preflight。微博未加载业务工具或尚无连接时只允许 prepare_weibo 准备路径，不读取 OAuth 状态或触发连接锁，加载工具之后仍不宣称授权与额度有效。

已知 UNAVAILABLE 的新委派在创建任务和消耗领域执行预算之前拒绝。任务真正启动前、领域 Agent 构建前及业务工具调用前再次检查，发现时的旧快照不能绕过后续停用。PREPARATION_REQUIRED 阶段即使只读业务工具也不能越过准备白名单。人工批准前发现能力不可用，不消耗最后一项批准；拒绝全部待执行操作和取消任务仍可进行。准备完成后仅使用当前实际工具目录和原权限边界。

检查器失败或返回空值按不可用处理，错误详情、凭据和本机路径不进入模型消息。健康状态不改变技能版本或替代业务回执核验，也不能撤回已经发出的请求。当前没有网络健康保证、故障自动重试、配额轮询或后台探活；主模型和管理工具自身仍消耗现有执行预算。新增领域可通过 DomainDefinition 的 availability 提供可信本地检查，旧三参数定义按工具存在与否给出保守默认状态。

## 关联操作核查与跨会话保护

写操作开始前由运行时生成逻辑 UUID 并写入操作账本，和模型产生的工具调用编号分离。腾讯创建工具通过 OperationBoundTool 接收服务端注入的逻辑编号和凭据范围；这些字段不在模型参数 schema 内，模型传入时会被拒绝。逻辑编号用于本地关联，不是供应商幂等键，不承诺外部系统 exactly-once。

桥接层收到真实创建响应后，在输出给 Java 前将脱敏回执以独占文件、临时文件 fsync 和目录 fsync 方式保存到凭据对应目录，已有编号不能覆盖。核查通过 reconcile_operation 引用当前会话的 taskId/operationId，适配器只读取对应凭据与 UUID 的回执；有匹配回执时追加当前订单查询。没有关联回执则不查询供应商，不能把另一个当前订单认作本次提交，也不把查不到订单当作未执行。核验仅确认原始创建是否发生，当前订单信息另列，不证明履约完成。

只有持久账本、原始关联回执和严格创建响应校验同时匹配时，UNKNOWN 操作才可被标记为业务结果已核实。任务本身仍保持终态，不能重跑。核查消耗管理工具及供应商读取预算，不自动轮询；本轮离线验证没有调用真实供应商。进程在保存关联回执之前崩溃，或报价过期等本地拒绝尚无独立未提交证明时，仍保留未知，不提供手动“清除未知即重发”的接口。

operation_scopes 和 operation_claims 在同一事务中保护同凭据范围的未核实操作，先锁范围再更新任务和审计；跨会话竞争只能有一个成功入口。核实结果释放对应不确定性占用，后来的冲突证据会重新建立占用。当前范围基于腾讯凭据指纹，并非跨凭据轮换的稳定账号身份；旧操作缺少范围或逻辑编号时不伪造关联，沿用原保守限制。未接入该接口的供应商仍只有原会话内保护。本功能也不替代多副本的执行租约与检查点并发控制。

本次技能版本映射复核：桥接新增逻辑编号校验、回执落盘及禁止覆盖，城市/POI、报价失效、人工取消和禁止重试五条红线原文、断言入口及注入配对保持不变；仅更新 rules.json 的技能摘要，不修改 semantic_status 或 human_reviewed，不将固定模型测试升级为模型资格证据。

## 能力输入契约与短时事实

三个生产领域共同发布 default、ride-quote-context 和 resource-context。default 处理独立任务，不接收跨任务 inputs；ride-quote-context 要求别名 rideQuote、类型 ride_quote；resource-context 要求别名 resource、类型 provider_resource_reference。后两者仅允许 PREPARE，用于以事实为背景的查询与分析。缺别名、多余别名、未注册契约或扩大执行范围，在创建任务前拒绝；事实类型错误在领域模型启动前拒绝。契约内容与技能摘要共同组成 executionVersion，修改契约会使旧待恢复任务失效，即使技能文件没有变化。旧 JSON 缺少 inputContract 时按 default 读取，不将旧记录补造成新契约的验证结果。

TencentQuoteFactExtractor 仅接收实际 tencent_ride 的 estimate-price 返回。核对桥接退出码、HTTP 状态、业务码、错误字段、单位、报价时间、已选择的上下车点、车型及金额；字符串金额、负数、非整数分金额、重复 JSON 键、未来时间与已过期结果均不生成事实。适配器按桥接 quotedAt 加五分钟计算失效时间，不按 Java 收到响应的时间延长。快照保留实际上下车点名称、米、秒与分金额，明确区分路线预计时长和司机 ETA；不证明供应商锁价、库存或未来履约。

快照不交接 estimateKey、priceEstimateKey 或 stateVersion。现有报价和行程草稿属于原子会话，跨子会话复制这些字段不能得到可用且可信的下单状态。下游若需叫车，仍须由出行任务在自身草稿内完成地点确认、询价、摘要和逐次人工批准。本阶段没有自动订餐触发器、可转移的下单报价凭证或跨领域写动作事务。

FactExtractor 由应用配置注册，主 Agent 和客户端没有提交事实值的接口。匹配的工具在联系供应商之前先向 PG 写入 FactObservation 失效标记；重新询价、修改 POI/草稿及相关写动作会遮蔽旧快照，失败和超时也不会恢复旧值。返回时再写证据摘要、完整返回值的指纹和经提取器确认的事实；校验完整输出的上限为 128000 字符，保存原文摘要的上限为 16000 字符，摘要不能用于重建精确原文。每项任务最多保存 32 条观测，满额时停止新的相关调用，不淘汰历史后继续执行。

同一事实键只投影最后开始的观测，较早查询的晚到成功不能覆盖后来失败的刷新。开始和返回各有独立审计事件，更新锁定当前目标与任务行并检查任务仍在运行；取消、目标修订或进程中断后，不发布晚到的报价事实。事实及证据存于任务 JSON，恢复时保留；旧 JSON 缺少 observations 时按空列表读取。已保存的历史观测可供审计，不代表它们始终有效或对下游可见。

绑定时、工具边界、人工批准恢复前和任务完成时继续检查版本与有效期。运行中输入过期会阻止后续工具，并使晚到的完成结果转为 STALE；已经发生副作用的任务保留 UNKNOWN 核查路径。生产跨任务快照契约均为 PREPARE，不授予写权限。全局修订仍保守失效，选择性重规划、按字段补问和所有业务动作的强类型输入约束仍待后续阶段。

本地验收包括严格报价解析、刷新失败后失效、乱序返回、过期阻断、取消后的晚到证据、旧 JSON 兼容、契约变更以及实际领域 ReActAgent 间的隔离交接。真实 PG 验证重载、并发观测不丢失及审计失败回滚。模型和供应商均使用 test double，不以这些断言替代真实模型规划质量或线上报价资格验证。
