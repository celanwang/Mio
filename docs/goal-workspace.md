# 从意图到交付的目标工作台

统一目标是把持续目标模块连接成用户可以完成的产品流程。三阶段已接通：目标总览与阻塞动作；意图规划、补问与继续；版本化交付与持久进展通知。

## 使用流程

在开启 Multi-Agent 的应用中打开 goals.html。可从已有对话进入，也可在工作台直接输入目标并创建。目标列表支持重新打开已有目标，无需先发送聊天消息。

“根据意图生成计划建议”使用单次、无工具的模型调用，读取实际用户目标和当前注册能力，生成字段及步骤建议。调用共用累计目标预算，最长等待40秒；模型不能启用后台执行或直接修改确认计划。用户审阅后保存，才采用该建议；已有计划不会被建议覆盖。

工作台集中展示尚无计划、等待、执行中、补问、阻塞、过期、暂停、关闭和准备就绪等状态。补问在对应步骤回答，使用现有 questionId 与任务恢复协议，不扩张其他步骤授权。已接收回答可以继续；失败步骤可以显式重新准备；可关联的未知业务操作可以核查，未提供核查适配器时提示人工处理，不自动重发。

## 交付

“汇总当前交付报告”保存不可变 Markdown 快照，包括用户目标、确认字段、条件、各步骤输出和证据评估、待处理事项、业务资源及其来源。阻塞期间也可以保存部分报告，只有当前准备结果完整且无未知业务操作时才能确认交付。

相同来源重复汇总返回同一版本；字段、计划、任务结果或资源证据变化后产生新版本。确认时再次校验当前来源和版本，旧快照仍可下载但不能当作当前结果确认。确认的范围是 PREPARATION_REPORT，不会确认供应商履约、批准工具调用或关闭目标。用户确认记录和审计一起持久化。

后台推进完成及意图规划后，进展通知写入 PG。同一来源状态只登记一次；页面刷新和重启不会丢失已读状态。通知只在本机工作台展示，不发送邮件、聊天消息或系统推送。查询页面不会调用模型。

## 接口与实现

GET/POST /api/workspace/goals 列出或创建目标，GET /{session} 聚合工作台；POST /{session}/plan 生成未采用的建议；/answer、/continue/{task} 和 /reconcile/{task}/{operation} 复用已有执行链。POST /{session}/deliveries 创建交付，GET /deliveries/{id} 下载内容，POST /deliveries/{id}/acknowledge 确认当前版本。通知通过 /notifications/{id}/read 标记已读。

goal_deliveries 保存交付版本与来源哈希，goal_notifications 保存去重通知和已读状态，表由应用启动幂等初始化。新表纳入已有维护预览和锁定范围。原来的步骤编辑、并行、事实绑定和能力包见[持续目标说明](continuous-goals.md)。本轮只做工作台核心流程定向回归与整体验收，不调用真实付费模型或供应商。
