# 持续目标执行

统一目标：在明确范围、预算与期限内持续推进用户目标，支持局部修订、事件唤醒、可信业务状态跟踪、并行准备和能力扩展。沿用现有目标、任务、权限、预算与 PostgreSQL，不引入新的流程框架。

| 阶段 | 功能交付 |
| --- | --- |
| 1 | 结构化字段、版本化步骤、局部修订、计划建议和页面管理 |
| 2 | 持久唤醒、定时推进、有限执行额度、暂停及重启恢复 |
| 3 | 已核实业务资源与追加状态观测、履约视图 |
| 4 | 独立准备步骤的有界并行、方案字段比较 |
| 5 | 信息检索与文档助手、文档导入和交付物保存 |
| 6 | 配置驱动的能力包、准备型远程 Agent 适配 |

后台只执行用户确认的 PREPARE 步骤。写入继续走前台已有权限和批准。准备任务的完成、业务资源的创建、履约状态和目标条件分别展示。每阶段验证关键行为，最后运行一次现有完整离线入口；不以测试数量代替功能。

## 使用

开启 MIO_MULTI_AGENT_ENABLED 后先创建对话目标，再点击目标区域的“持续目标”。主助手也可以用 propose_goal_program 生成建议；建议仅保存在待确认区，不自动启用。页面可直接维护字段、步骤、依赖、输入输出契约、数值条件和执行范围。

保存后可“推进一次”，或勾选后台准备并指定期限、最多唤醒次数、间隔与并行数。每个计划最多12步、20个字段、100次唤醒，期限最多七天；每次后台执行最多两分钟，沿用单轮和累计目标预算。唤醒次数不因修改字段重置。范围启用后即使关闭页面也会推进；页面暂停目标会中断后续执行，恢复 ACTIVE 后仍启用的后台计划可以继续准备。需要彻底停止自动推进时取消后台准备并保存，或关闭目标。

步骤以字段版本和自身代次标识。修改字段只重建声明相关的步骤及其下游；没有声明字段的步骤保守视作依赖全部字段。已完成的旧结果保留历史，但添加失效标记；无关步骤保留。自然语言追加用户消息仍沿用现有整体目标版本规则，需要刷新确认计划；结构化字段不被扩张为业务写入批准。运行中的步骤应先暂停目标，再修改受影响字段。

前置报告可由领域 Agent 通过 mio_read_dependency_report 按已声明依赖读取，不能将报告文字当成业务事实。可信事实使用输入契约和别名绑定，页面每行填写“别名=前置步骤/事实key”，例如 rideQuote=quote/ride.quote，输入契约选 ride-quote-context。事实按实际证据版本、类型和有效期绑定；缺失或过期时阻止下游。步骤选择 report 只表示工作报告就绪，VERIFIED 表示所选业务输出契约的当前证据满足；步骤条件不满足时不推进依赖。原有目标验收接口不被自动确认或替换。

独立能力的准备步骤最多并行四项，同一能力串行，避免供应商草稿和账号资源竞争。可信数值比较按单位分组，不混合单位，也不自动下单。事实过期时，下次唤醒会为来源及下游建立新的准备代次；中断的已启动任务不会按原编号重放，用户可显式重新准备。所有报告准备完且没有资源跟踪时，停止周期性空转；有短期事实时等待其到期再刷新。

## 资源、文档和能力

已核实创建回执登记业务资源；关联查询追加供应商观测。当前腾讯适配器核对资源编号后保留供应商状态与说明，不猜测未有明确定义的数字状态是否代表履约。用户可追加自己的核实结论，来源为 USER_REPORTED，不能据此解除未知操作占位或生成供应商证据。可在确认计划时单独允许关联资源查询，查询仍消耗工具额度，不自动取消、支付或重新下单。其他供应商没有可信回执适配器时继续保持未知。

信息研究助手读取用户主动导入的本地文档；配置 MIO_RESEARCH_SEARCH_KEY 后可使用 Brave 网页搜索，缺少凭据时明确不可用。只取得搜索摘要，不自动抓取任意网页或声称阅读了全文。文档助手支持文字/Markdown 的阅读、摘要、比较和改写，回复作为任务报告保存；用户点击“保存为文档”后写入工作区。单篇正文最多十万字符，Agent 每次读取最多两万字符并明确截断。当前不解析 PDF/DOCX 二进制文件，也不向外部应用发布。导入文档是单用户本机工作区资料，不进入全局长期偏好。

agent-packages/*.json 为管理员启动配置，示例默认 disabled。LOCAL_DOCUMENTS 将现有只读文档工具装配为专门领域；REMOTE_PREPARE 使用管理员提供的 HTTPS 端点及环境变量中的只读令牌，模型和网页不能安装能力或修改端点。修改后重启，清单与技能内容的哈希参与任务能力版本。

远程桥接协议是 mio.prepare.v1，POST 请求为 {protocol,mode:"PREPARE",request}，响应要求 {protocol,state:"COMPLETED"或"NEEDS_INPUT",reply}。不传递本地批准、业务凭据或状态写入能力；远程服务必须用只读凭据并遵守 PREPARE 契约，远程正文只作为未核验报告。本实现不是完整 A2A 协议服务；需要 A2A 时可在该适配边界增加协议客户端，不改核心任务运行时。

## 运维入口

GET/PUT /api/goals/{session}/program 管理确认计划；GET /status 查看步骤和唤醒；POST /wake 登记带 requestId 的幂等推进；POST /refresh 为明确步骤及下游创建新准备代次；GET /compare 按 fieldId 读取可信比较结果。资源在 /resources，文档在 /api/documents。均沿用本机 API 访问控制。

唤醒持久保存在 goal_wakeups，用户配置与定时器在 PG 中恢复。准备步骤沿用现有队列、会话租约、预算和任务状态；前台忙碌时延后，不抢占会话。保存状态与唤醒事件在同事务登记，消费者不在数据库事务内调用模型。进程中断的旧激活标记失败，不把已启动任务重新提交。备份恢复维护会关闭已有后台计划并作废待执行/运行中的旧唤醒，需要用户重新确认后台范围。

阶段功能完成后，运行 ./scripts/eval-postgres.sh 做一次整体离线验收；针对功能可使用 ./scripts/eval-postgres.sh -q -Dtest=JdbcGoalProgramsIntegrationTest test。不会连接付费模型或真实业务，远程桥接测试仅使用本机合成 HTTP 服务。
