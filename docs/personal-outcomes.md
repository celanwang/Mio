# 从个人意图到业务结果

统一目标：贯通个人偏好、方案选择、受控执行、结果跟进及用户纠正。沿用既有任务、审批、预算、证据和后台准备机制。

分阶段落地。第一阶段保存用户选择及其来源版本，将明确的执行要求交给独立前台任务；旧报价只作为准备依据，执行任务重新核对，写操作仍逐次审批。第二阶段统一个人化上下文，提供来源、适用范围、到期与目标例外，人工修改按版本提交，自动化状态和审计同事务变更。第三阶段提供受信配置的领域事实与回执适配、结论到具体论据的关联，以及受用户范围约束的资料到期、资源变化和指定时间触发。最后把业务结果与用户反馈回接工作台。

不猜测真实供应商返回格式；没有已验证契约的输出继续标记为报告或未知。用户反馈是用户报告，不覆盖供应商回执。偏好不授予权限，选择方案不等同于批准工具，触发器不发出业务写入。实现后执行必要离线与隔离数据库回归，按 main 现有风格阶段提交。

## 方案选择与执行

工作台的多条件比较可以“选用此候选并填写执行要求”，也可以从“方案选择与业务执行”读取已完成步骤，明确选择是否沿用某次仍有效的比较。保存选择时核对目标、计划、任务及证据版本；关联比较时还检查候选确实满足该次条件。记录保留步骤、用户确认字段、原报告、事实快照、比较条件及本次明确执行要求。

保存选择不创建业务调用。用户再次点击创建执行任务时，服务端把这次选择登记为真实用户表达，推进目标版本，旧准备计划不再代表新的执行目标。独立执行任务使用新子会话，不复用准备阶段的报价密钥，仍通过现有工具审批链。mio_read_selected_context 仅能读取服务端绑定到本执行任务的选择，分 SUMMARY、REPORT、FACTS 三部分返回；历史资料作为数据，不提升成新授权。

原契约要求的可信准备事实必须在当前执行任务重新取得。原步骤条件与已选比较的硬条件在写操作前确定性核对，记录证据有效期限及任务版本；核对后发生并发草稿变更或证据过期也会阻止发送。支持字段以已注册事实契约为准，未配置可信格式的领域不能宣称完成相同程度的确定性核验，仍依赖技能流程和具体调用确认。偏好权重只描述方案取舍，不是硬条件或工具权限。

执行请求先持久化，重复点击不再次调用领域助手。任务创建前进程中断时也不会自动重发，需核查后重新准备与选择；不以“没有查到任务”推断没有发生业务操作。参数变化、报价过期或条件不满足时原批准不能绕过检查。检查由任务运行时与事务内提交关口共同执行，聊天页和工作台审批路径一致，不能用额外的业务任务绕过本次选择；追加业务需新的明确用户要求。补问、具体调用批准/拒绝、关联核查在对应执行任务处理；结果 UNKNOWN 不重试提交。

GET/POST /api/workspace/goals/{session}/selections 读取或保存选择。选择请求包含 requestId、expectedRevision、expectedGoalRevision、stepId、evidenceHash、可选 comparisonId、instruction。POST /{id}/execute 创建一次前台执行，POST /{id}/approve 只接受该选择对应任务的 confirmations。选择与批准是不同操作。

执行视图显示独立阶段、任务状态、回执及资源；准备报告确认不会自动批准或完成业务。交付报告关联用户选择、执行任务及反馈。反馈接口 /{id}/feedback 支持 HELPFUL、NEEDS_CORRECTION、USER_REPORTED_DONE、USER_REPORTED_FAILED，附明确说明和幂等 requestId。反馈持久化并进入后续规划参考，可由用户在偏好区域进一步明确纠正；它不修改供应商回执、解除未知操作占位或自动授予权限。

## 一致的个人化上下文

PersonalContext 为独立规划、主助手和领域助手提供同一来源的有限偏好视图。全局偏好与相关领域偏好按适用范围加入，保留人工/推断来源、页面版本、到期及截断标记；最多12页、12000正文字符。实际用户表达和已确认硬条件优先。偏好读取故障只导致缺少个人化，不生成默认偏好，也不阻断权限检查。单 Agent 的画像读取同样过滤已到期页面。

“个人偏好与纠正”提供原文、版本、到期、来源与纠正原因。自动提炼在画像版本变更时记录源消息编号；来源消息已忘记或不存在时明确显示不可用，旧记录没有证据时不反推原文。人工修改按 expectedRevision 提交，更新后的人工页面不被自动提炼覆盖，过期页面不继续注入。删除保留防止后台重新创建的标记。

“本目标暂不使用”只记录目标例外，恢复参考也不修改长期偏好或原有硬条件。偏好、例外或用户反馈变化会改变规划证据哈希，旧建议与选择需重新核对。

GET /api/profile/details 返回当前版本及期限；/api/profile/explain?id=... 返回来源记录。PUT /api/profile 新增 expectedRevision、expiresAt、reason；新建使用版本0，已有页面需实际版本，DELETE 也需 expectedRevision。GET/POST /api/workspace/goals/{session}/preferences 读取相关参考或登记 profileId、excluded、reason。画像来源管理不清除目标、SDK 上下文、业务回执和既有交付快照。

传统习惯自动化仍保留 session-start 语义，其状态迁移收紧为 PROPOSED→ACTIVE/REJECTED、ACTIVE→REJECTED，不允许已拒绝或吊销规则被旧批准请求重新激活。提议、决定和批量吊销与对应审计同事务提交，审计失败不保留成功状态。内核权限链独立生效。

## 领域证据

证据适配文件在 evidence-adapters/，可用 MIO_EVIDENCE_DIR 指定路径。它们是只在启动时读取的受信开发配置。READ 用严格成功条件、JSON Pointer、数值/文本类型、明确单位、本地短时窗口与失效工具生成事实；WRITE 只在成功条件和字符串资源编号同时核实时证明创建。契约进入能力注册表、多条件比较及能力版本。修改配置后旧批准、旧任务不按新契约重新解释。

默认餐饮和微博示例关闭，字段仅说明配置结构，不代表真实供应商格式。需按已核实的当前工具及脱敏响应建立契约；没有证据就保持报告或 UNKNOWN，不用模拟回执冒充真实接口。本次不联系实际供应商。内置出行核验继续使用专用适配器，不接受配置覆盖。详细格式见[证据契约目录](../evidence-adapters/README.md)。

## 受限事件触发

触发器绑定已确认计划及目标版本，支持 AT_TIME、EVIDENCE_EXPIRING、RESOURCE_CHANGED。动作仅有本机通知和指定准备步骤及下游刷新。自动刷新要求计划已允许后台准备，受原能力、期限、唤醒及累计预算约束；存在未知操作时等待核查。通知不调用模型或联系他人，刷新不创建 REQUEST_APPROVAL 任务。

每个目标最多20条活动触发器，冷却至少60秒，窗口不超过计划期限及未来七天，每条至多100次；指定时间只触发一次。事件指纹、行锁和持久次数抑制重复。资源变化按稳定资源编号、状态、来源及证据内容去重，新回执编号或观测时间本身不会触发刷新。手动计划或目标变更使旧触发器 STALE，目标暂停时等待，关闭时停止。连续三次处理失败记录 FAILED 并停止，状态可在页面查看；需重新确认范围后创建新规则。恢复备份时将活动触发器暂停。

GET/POST /api/workspace/goals/{session}/triggers 读取或确认范围，POST /{id}/pause 携带 expectedRevision 停止。请求包含 kind、action、stepIds、at、until、cooldownSeconds、maxActivations 及当前计划/目标版本。与原有后台准备共用调度器，不能由模型安装或修改。

## 结论与具体论据

综合调用的 sourceCatalog 由服务端生成，包含当前事实编号及版本、精确报告片段，以及用户显式加入本目标的文档范围。每条新 finding 必须给出目录内 referenceIds，并标记 SUPPORTS、CONFLICTS 或 UNCERTAIN；涉及步骤时编号必须与论据匹配。模型返回的 sources 内容不采信，最终保存的来源由服务端绑定。旧综合快照保持兼容，但不会被补写成精确论据。

工作台可在读取文档后加入最多2000字符的明确范围，GET/POST /api/workspace/goals/{session}/sources 管理当前目标引用，DELETE /{id} 移除。文档更新使旧范围 STALE，删除文档移除派生引用；历史交付快照按原策略保留。生成期间来源变化不发布新综合。报告导出保留论据原文、位置、版本和类型，明确区分模型报告、原始文档及可信事实。

核对的是引用身份与版本，不是自动证明语言结论得到来源支持。模型对冲突及取舍的解释仍需真实使用审阅；未引入无限制 judge 链或新的付费验证流程。

## 运行与数据

新增 V006 至 V009 迁移分别管理选择反馈、个人化元数据、事件触发和文档论据。都由统一迁移器执行，不修改已应用脚本。维护摘要、恢复暂停及锁定范围覆盖新表；运行诊断展示触发器、选择、索引积压和已配置的证据适配器。契约目录加入源码指纹，默认实例不因示例文件启用新核验。部署需一并携带 skills、agent-packages 及已审阅的证据契约目录；自定义外部目录须单独管理版本，运行时能力版本仍包含实际契约内容。

离线回归使用模拟模型、供应商响应和隔离 PostgreSQL；真实模型质量、供应商格式有效性、实际成本及履约效果不由这些测试建立。
