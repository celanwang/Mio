# 长期使用与运行治理

统一目标：让 Mio 的目标可以接续、知识可以管理、配置和升级可控。已落地目标生命周期、知识生命周期、工作区连接、出行跟进、模型配置和数据库迁移六部分；沿用已有权限与证据边界。

## 长期目标

任务容量限制现在只计算非终态任务；历史完成、取消、失效和失败任务不会挤占活动容量，未知操作仍单独阻止重复提交。主助手默认读取活动、待核查和最近任务的精简视图；历史任务通过 read_task 按编号读取，原始报告与回执不删除。用户历史页按稳定编号游标分页，不代表按时间排序。

目标工作台增加“目标接续与历史”。续期可以延长未来七天内的执行窗口，并增加至多100次唤醒；累计上限最高10000。可同时显式追加模型、工具、任务及 token 上限，需填写原因。原有调用、token 下界、待结算和未知用量、历史覆盖标记均保留，不因续期退款或清零。每次额度追加与审计同事务提交。

上下文达到容量前，可由用户确认本阶段完整有效的目标摘要。旧 GoalRecord 原样归档，新的摘要成为用户明确确认的新目标版本；旧计划与批准不再恢复，需要重新确认计划。目标编号、累计预算和未知业务操作不变。模型不能替用户确认摘要，历史摘要也不会自动升级成新授权。

接口：/api/workspace/goals/{session}/renew、/context、/history、/contexts。

## 知识生命周期

情景向量使用 episode_vectors，按服务端点、模型、1024维及预处理版本组合出的 namespace 隔离。原文摘要参与有效性检查；不同模型或过期原文不会混入当前召回。旧 embeddings 数据保留，不自动声明属于当前模型。当前命名空间按独立游标和作业编号补建，额度仍受知识调用账本限制；旧模型任务不阻塞当前补建窗口。更换模型后可能先出现召回不足，补建完成后恢复，不能把旧数据直接改标签。

文档按1200字符、150字符重叠分块，引用包含文档编号、revision、start_offset/end_offset。关键词查询无需模型；配置向量服务后可以显式按16块一批建立当前模型索引，查询采用关键词与语义结果的 RRF 融合，同篇文档最多返回三块；引用可以按版本、偏移和原文核对。文档更新删除旧派生块，索引返回时再次检查版本；错误版本的结果不发布。读取工具可按 startOffset 分页，expectedRevision 可防止读取过程中版本漂移。

工作区支持读取、编辑、导出 Markdown、构建索引和删除文档。后台索引需用户显式启动，可以读取进度、暂停和恢复；每次处理16块，租约失效或暂停后不发布旧结果，更换文档或模型版本后取消旧任务。删除会级联删除分块和语义索引，但不改写原来交付报告的历史快照。知识向量调用使用 UTC 日调用/输入/token 账本；它包含新增文档索引与语义查询，不能理解为仅后台消费或供应商总账。

情景回忆有单独的原文管理入口。忘记一条情景会移除原文、对应作业、向量及来源实体，保留无正文的删除标记；SDK 再次回放相同消息编号时不会重新登记。画像、SDK 会话上下文、用户目标、交付快照和业务证据是其他数据范围，不随此操作删除。明确区分“忘记情景”和“清除全部个人数据”。

## 业务状态与统一工作区

工作台链接可打开同一个目标的对话，而不是新建无关会话。导航、知识管理、目标接续与诊断在同一页面可达。业务资源可单独停止/恢复后台跟踪；停止跟踪不代表取消订单。

腾讯关联核查先核实本地创建回执，成功后按确切订单号 query-order 查询；不会用另一个进行中订单代替原操作。响应仍核对业务编号。供应商费用字段按原字段展示，不猜测货币或单位。可信供应商状态可通过 app.resources.tencent-statuses 配置“供应商原始状态 → CREATED/ACCEPTED/IN_PROGRESS/COMPLETED/CANCELLED/UNKNOWN”的映射；默认不猜数字含义。映射需依据实际供应商契约配置。已由供应商证据核实终结的资源停止自动轮询，人工报告仍单独标记来源，不解除未知操作占位。测试不联系真实供应商。

## 模型、部署与迁移

ExecutionSettings 统一前台、后台、计划生成及目标级预算来源。计划生成取配置与40秒/单次调用/12000 token 的较小边界，后台取配置与两分钟上限。诊断 /api/system/readiness 展示模型配置、当前向量命名空间、预算、迁移记录、队列及本地能力观测，不显示密钥、不调用付费模型或探测供应商。传统单 Agent、协作目标及知识调用存在不同统计范围，页面不能把它们合并成精确账单。

生产由 SchemaConfig 的唯一初始化器执行 db/migrations/V001__unified_schema.sql、V002__knowledge_backfill.sql，以及 V003 至 V005 的索引任务、比较和综合快照迁移。通过 PG 事务咨询锁、版本号与 SHA-256 校验串行迁移；已应用文件不可修改，后续变更新增版本。V001 幂等接纳现有表并补齐结构，V002 补建文档分块及新元数据。启动需要数据库可用且迁移成功；运行期画像读取的降级方向不变。领域存储的 initialize 方法继续供隔离测试使用，不再作为生产多套初始化器。

升级前备份并停止旧进程，再启动当前版本；不混合运行旧表写入路径。PostgreSQL 状态表和关键事务审计共同构成恢复依据，普通链路日志仍为 best-effort，不能声称仅凭 events 可重建全部状态。旧恢复流程与维护入口继续使用，新增表纳入维护摘要和锁定范围。

Compose 中 PostgreSQL/Redis 默认只绑定127.0.0.1；Redis 当前未接入，不应据其运行状态宣称短期记忆已持久化。公网访问或多用户部署仍需要独立身份与权限设计，不能仅关闭 local-only。
