# 项目订单流程

## 下单成功与支付

用户选定车型并同意后，用 `tencent_ride_create_order`，顶层直接传 `price_estimate_keys`、`stateVersion`、`summary`（可选 `user_prefer_labels`），通过本次“允许 / 拒绝”确认创建即时订单；不套 `command` 或 `parameters`。先核对业务 code 和真实订单号，再展示行程、预估金额与订单状态。创建订单不代表支付完成、司机接单或行程结束。

现有工具不提供付款二维码、支付链接或支付接口。不要生成收款码，不要把预估金额当作付款账单，不要求先扫码才能下单。用户要求必须先支付再下单时，说明当前接口不支持并保留在询价阶段。订单需要支付或平台校验时，引导在微信的腾讯出行服务小程序中打开对应订单处理；只在真实结果确认支付完成后报告已支付。

## 查询订单

用户请求当前订单状态时调用 `query-order`；仅需确认是否存在订单时用 `query-ongoing-order`。脚本内部使用用户账号的进行中订单。所有订单号、司机姓名、车牌、位置、时间和费用来自实际结果，缺失则说明未提供。区分正在派单、等待接驾、司机到达、行程中、待支付、已完成和已取消。已结束订单不保证能从“进行中订单”接口查到，必要时到小程序查看历史。

用户在下单时已要求师傅信息和车牌，成功后主动 `query-order`，读取 `driver.name`、`vehicle.plate`；仅有进行中订单结果时可读取真实 `licensePlates`。派单中说明司机尚未分配；不要求先支付，不声称工具没有查询能力。失败后先查询当前订单，向用户报告实际原因，本轮不自动重试下单。

## 查询司机位置

调用 `query-driver-location`。按真实 orderStatus、driverLocation、eda（米）和 eta（分钟）展示；无司机位置时说明当前状态，不凭距离推算。只按请求查询，不后台轮询。

## 取消订单

1. 用户表达取消意图后，调用 `check-cancel-fee`；可传 reason。此工具只查询订单与费用，无论是否免费都不会取消。
2. 展示返回的真实 orderId、amountYuan、原因，说明即将取消该订单。
3. 用 `cancel-order`，parameters 包含该 orderId、amountFen 和可选 reason，summary 包含订单与费用，进入项目本次“允许 / 拒绝”流程。免取消费也要确认，不能复用下单批准。
4. 后端重新核对当前订单和费用。`fee_changed` 表示未取消，展示新费用后重新确认；订单变化时重新查询。
5. 核对 `result.body.code` 和返回状态，才能报告取消结果。超时或失败先查单，不自动再次取消。支付取消费是否已完成以平台返回及小程序为准。

原版 `cancel-order` 在无费用时会直接取消，本项目通过适配层拆分了查费与取消，不调用这一原版自动分支。
