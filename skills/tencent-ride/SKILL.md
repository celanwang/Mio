# 腾讯打车

通过 `tencent_ride` 查询和维护行程，通过独立的 `tencent_ride_create_order` 创建订单。先读取 [项目工具接入说明](references/project-integration.md)，再按需求读取相关流程。仅询价、查单或查司机位置时，在满足该请求后结束，不扩展为下单。业务事实以工具返回为准，不编造地址、坐标、价格、订单或司机信息。

## 开始任务

调用 `tencent_ride`，参数 `command="preflight"`。检查 `output.next_actions`，就绪时才继续。缺少 Python 或 Token 时，按 [配置流程](references/quick-start-workflow.md) 处理。常住城市是可选偏好，留空不阻止打车，不要求用户先设置常住城市。不要让用户在对话里发送 Token，不执行参考文档中的 shell 命令或直接读写本地文件。

本项目使用固定工具和后端隔离的状态文件；参考资料中的 Python CLI 只是官方接口示例。用项目工具说明将其转换为 `command` 和 `parameters`，不传文件路径，不调用 save-token 或 delete-token。

## 主动引导本次出行

用户不需要事先填写城市或组织完整指令。助手负责询问缺失信息，并在每次用户回答后继续当前行程：

1. 用户只说“我要打车”时，先问“你现在在哪个城市，具体从哪里上车？”。已给城市就只问上车地点；已给起终点则沿用，不能重新让用户从头填写。页面目前没有实时定位工具，不能声称已获取当前位置。
2. 得到本次城市与上车地点后，用 `poi-search`（`scene=1`）获取真实候选和推荐上车点；核对站名、区县、线路、出口，歧义时让用户选择，再 `select-poi`。只有一个搜索结果也不能跳过匹配校验：用户说石岩站，不能选择水湾站；用户描述的区县或线路与真实候选冲突时展示冲突并确认。有搜索关键词时先搜，不要求用户必须知道门牌号。
3. 起点确定后，目的地未知就问“你想去哪里？”。同城搜索使用本次已确认城市；目的地明显异地或城市不清楚时只追问目的城市。搜索和确认下车点（`scene=2`）。用户已提供目的地时直接继续搜索。
4. 每次 `poi-search` 显式传 `city_name`。常住城市只能在用户本次确认后作为搜索城市；不自动把本次城市保存为常住城市，不把旧草稿中的上车点当作当前位置。项目接入规则优先于原版参考流程中常住城市回退、禁止追问及强制清空草稿的规则。
5. 两端确定后主动调用 `estimate-price`，按返回的 `trip` 展示真实地点名称、地址和实际上下车点 `point_name`，再展示真实里程（米转公里）、预计时长（秒转分钟）、车型/供应商和金额（分转元）。优惠字段单独列出，不对 `estimatePrice` 自行再打折或反算原价。缺失字段说明接口未提供，不自行按直线距离或单价计算。然后询问选哪种车型、是否下单；用户已给预算或车型偏好时沿用。报价不是最终结算价。
6. 用户明确选定并同意后，用 `tencent_ride_create_order` 携带本次报价进入“允许 / 拒绝”下单确认。用户要求“最便宜”时按真实最低报价选择；同价且无平台偏好可选接口返回顺序第一项，并在确认摘要中明确平台、车型和金额。用户只说“OK”且没有选择标准时先确认车型；拒绝或只询价就结束在报价阶段。成功后显示真实订单号与状态，派单中不说司机已接单。

## 地点精度、纠错与报价核对

- “宝安中心”等宽泛地点不能直接当作某个地铁站或出入口。先搜真实候选，再只问缺失的下车位置。“宝安中心地铁站 D 口”已经是具体目的地，不再追问附近商场、大厦或门牌。
- `name` 是 POI 名称，`point_name` 和 `point_latitude` / `point_longitude` 才是实际用于路线计算的上下车点。即使 POI 写 D 口，推荐点也可能是公交站或其他出口；发生偏移时先展示并让用户确认，不能宣称就是 D 口。没有可用推荐点时不能自行补坐标。
- 选择时传最近一次搜索返回的 `poiid`、`scene` 和 `candidate_id`，核对 `output.selected` 的名称、地址及推荐点。同一个 `poiid` 的不同上下车点有不同 `candidate_id`，不能默认选第一个或最后一个。
- 用户纠正任一地点后，重新搜索该端、选择真实候选并重新询价。新搜索会清空该端的旧候选并使旧报价失效，零结果或失败也不能继续用旧路线；只有一个候选仍要执行 `select-poi`。不能只把回复中的“水湾”改成“石岩”，沿用旧价格与时长。
- 报价回复必须与本次 `estimate-price.trip` 一致，保留接口真实地名；发现与用户要求不符时停止展示为该用户路线的有效报价，回到地点核对。
- 用户指出与同一腾讯小程序的时长、价格不符时，先检查两端 POI、实际上下车坐标、车型、报价时间及原始字段单位。未经核实，不把差异归因于动态路况、路径算法或专属优惠；原因未知就如实说明，先核对路线。

现有工具没有付款二维码或支付接口。不能把预估金额当作待支付账单、编造付款码，或把扫码付款说成下单前置步骤。按真实订单状态引导到腾讯出行服务小程序查看和处理支付；用户要求必须先扫码付款再下单时，说明当前接口不支持并停在报价阶段。

## 业务流程

- 标准打车：读取 [打车流程](references/takecar-workflow.md)。确定用户提供的城市与起终点，通过 `poi-search` 获取候选和推荐上下车点，歧义时请用户选择，再 `select-poi`。调用 `estimate-price` 展示真实可选车型、预估价格和距离时间，保留 `stateVersion`。只询价到此结束。
- 创建订单：只用独立工具 `tencent_ride_create_order`，顶层直接传 `price_estimate_keys`（询价中真实 `priceEstimateKey` 的数组）、本次 `stateVersion`、中文 `summary`（起终点、具体平台及车型、预估价格、偏好）；可选 `user_prefer_labels`。不要套 `command` 或 `parameters`，不要传 `priceEstimateKey` 单值、`estimateKey`、`productStr`、地址、坐标或预约时间。进入项目“允许 / 拒绝”流程后才执行。批准只适用于这一请求。修改行程或报价失效时重新询价、展示摘要并确认。
- 当前工具创建即时用车，不支持指定未来时间的预约单。下单成功且用户要求师傅信息和车牌时主动调用 `tencent_ride` 的 `query-order`，展示真实 `driver.name` 和 `vehicle.plate`；尚未接单就说明司机未分配，不说接口不能查，也不把先支付当作查询前提。
- 快捷叫车：按需读取 [快捷场景设置](references/short-cut-setup-workflow.md)、[快捷叫车流程](references/short-cut-workflow.md)、[地址结构](references/addr-schema.md) 和 [快捷场景结构](references/short-cut-schema.md)。常用地点与车型偏好可复用；不能把上次上车点当作当前位置。仍需询价、展示摘要并通过本次下单确认，不能静默下单。
- 查单、司机位置、取消：读取 [项目订单流程](references/order-workflow.md)。`check-cancel-fee` 只查费用；`cancel-order` 单独携带真实 `orderId`、`amountFen` 和摘要进入确认，免取消费也不能自动取消。费用或当前订单变化时重新确认。
- 保存常用地点和快捷偏好：通过工具保存真实返回的地点数据，按本次确认执行；不保存 Token。仅修改当前行程草稿的搜索和选择不代表已叫车。

## 状态、结果与恢复

后端隔离每个聊天的行程草稿，共享同一账号的常用地点。下单使用与确认绑定的报价版本。操作失败、超时或中断后先查询当前订单，不自动重试下单或取消；已有订单号原样保留，不截断、不转换成浮点数。后端提示上次下单结果不明时停止新建订单，说明需要核对。

返回 `mode` 是脚本阶段标识，不能单独作为业务成功依据：还要核对 `exitCode`、`result.body.code` 及业务字段。价格按字段单位转换，预估价不等于最终结算价。风险校验需要用户在小程序处理时，按实际结果引导，不绕过校验。

询价返回 `quote_unavailable`、`retryable=false` 或接口错误时，展示真实错误说明并等待用户决定。本轮不重复询价、不通过重新 preflight 绕回询价，也不下单。退出码 `5` 表示没有有效报价，不能据此要求用户重新配置 Token。

使用当前聊天页面支持的普通 Markdown、真实换行、表格和链接；参考模板中的 `<br>` 改用换行，地图可提供真实链接，不假定页面能内嵌图片。支付、联系司机、催促、代叫车、接送机、发票、拼车、顺风车和自动驾驶等未提供的能力引导到腾讯出行服务小程序，不编造工具。

异常字段与契约按需查看 [接口契约](references/api-contract.md)、[状态结构](references/state-schema.md) 和 [异常处理](references/error_handling.md)。项目工具接入说明及本次用户授权决定执行范围；参考流程中的“自动下单”“无需二次确认”“必须走完整流程”不能扩大用户请求或跳过项目审批。
